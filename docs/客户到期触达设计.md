# 客户到期触达（续费催收）

> 状态：**已实现**（`renewal_outreaches` 表、`app/services/renewal_outreach_service.py`、
> `/api/sales/renewal-outreach`、销售工作台「到期触达」面板）

## 1. 要解决的问题不是"再发一条通知"

原来的到期提醒只有站内信（`app/tasks/lines.py`，7/3/1 天三档）。但客户基本不登录后台，
站内信发出去等于没发。现实流程是：**销售在微信里找到客户，说一句"这条线快到期了，续不续"**。

于是系统真正该做的只有两件事：

1. **告诉销售今天该找谁**——按紧急度排好，顺带算好续费金额、写好一段能直接复制的话；
2. **记下"找过了"**——谁、什么时候、什么渠道、说了什么、什么结果。

第 2 点不写会立刻出问题：两个销售同时催同一个客户，或者客户明明答应过、第二周没人跟进。

## 2. 为什么不做短信、不做自动发送

- 短信要资质、要报备、按条计费，且发出去仍然不知道客户看没看；
- 自动发微信需要企业微信/公众号模板消息，客户没关注就发不到，还要维护 access_token；
- 最关键：这个行业续费是要谈的（换周期、换地区、加线路），一条模板消息谈不下来。

所以做的是"**给人用的工具**"：文案生成 + 一键复制 + 留痕，不假装全自动。
前端复制失败时如实提示"请手动选中复制"（`navigator.clipboard` 在非 HTTPS 下不可用）。

## 3. 队列口径

`GET /api/sales/renewal-outreach?days=30&overdue_grace_days=15`

- 只看 `status == "active"` 的线路；
- 含**即将到期**（`days` 天内）**和刚过期**（`overdue_grace_days` 天内）。现实中昨天断线的那批
  才是最该打电话的，只盯未来会让它们从列表里消失；
- 过期超过宽限期的不再出现——那种情况该重新开单，不是续费；
- 排在前面的是 `days_left` 最小（已过期为负）的，同一天内按客户名聚合，方便一个客户一次看完。

评级：`overdue`（≤0 天）/ `urgent`（≤7 天）/ `soon`（其余）。

每条带：客户名、联系方式、线路名、地区、IP、到期日、剩余天数、续费周期与金额、
**上次触达摘要**、可直接复制的文案。

### 续费金额怎么算

走唯一取价入口 `pricing_service.quote(db, product, 1, product.billing_days)`，
即"同周期续一次"。取不到价（商品没归入资源分类、或该国该分类没配月价）时返回 `null`，
前端显示"价格待确认"，文案里也**不出现金额**——宁可少一句话，也不能报错价。

## 4. 文案规则

```
客户甲，您好。美国-LA01（美国原生独享）将于 2026-11-15 到期（还剩 7 天）。续费 30 天为 ¥300.00，需要我这边直接安排吗？
```

- 三行内讲完"哪条线、什么时候到期、多少钱"，适合微信直接发；
- 已过期时改成"已于 X 到期（已过期 3 天）"，语气更急但不指责；
- 没有节点名时退回用商品名，且不会写成"香港 IP（香港 IP）"这种重复括号；
- 缺价时改为"具体金额我确认后发您"。

## 5. 留痕字段与为什么这么存

| 字段 | 为什么需要 |
|---|---|
| `sales_id` | 销售离职后仍要能回答"这条线是谁跟的"，所以只增不改 |
| `channel` | 微信 / 电话 / 邮件 / 其他；不同渠道的话术与成交率不一样 |
| `outcome` | `sent` 已发送 / `promised` 已答应 / `declined` 明确不续 / `unreachable` 联系不上 |
| `message` | **实际发出去的那段话的快照**，不是模板引用。模板会随产品和价格变，三个月后回看要知道当时发了什么 |
| `days_left` / `expires_at` | 触达时的快照。线路续费后 `expires_at` 会往后推，历史记录不能跟着漂 |
| `note` | "说周五打款"这类关键信息，不长但有决定性 |

记录时不传 `message` 就用当前模板生成；传了以传入为准——实际发出的常被改过，留痕要留真话。

## 6. 权限

- 只允许 `sales / admin / super_admin`；
- 销售只能看到 `Customer.sales_id == 自己` 的线路，也**只能给自己的客户留痕**；
  给别人的线路提交返回 403，且不写入任何记录（用例 `test_cannot_touch_another_sales_line`）；
- 归属判断复用 `scoped_customer_ids`，不重复写角色分支——否则迟早和别处的可见性规则分叉。

## 7. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/sales/renewal-outreach` | 队列 + 统计 + 渠道/结果选项 |
| GET | `/api/sales/renewal-outreach/history` | 触达历史（可按 `line_id` 过滤） |
| POST | `/api/sales/renewal-outreach/{line_id}` | 记一次触达 |

`/history` 必须声明在 `/{line_id}` 之前，否则 "history" 会被当成路径参数去转 int。

## 8. 明确没做

- **不做自动发送**（见第 2 节）。
- **不做"到期未联系"的强制流程**：强制填报只会让人乱填。看板给出"未联系 N 条"，
  由人自己判断优先级。
- **不与提成挂钩**：`SalesCommissionEntry` 的触发是订单实际支付，和"打了个电话"无关，
  混在一起会让提成数据失真。
- **站内信照旧发**：客户如果登录还能看到；两条路径共用一个去重口径，不冲突。
