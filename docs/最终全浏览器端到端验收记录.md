## 2026-10-26 Playwright Chromium 补验

浏览器桥接仍不可用，本轮改用临时目录中的 `playwright-core` 驱动本机 Chrome（`C:\Program Files\Google\Chrome\Application\chrome.exe`），通过真实页面 DOM 操作，不直接调用业务 API 代替页面操作。前端服务为 `http://127.0.0.1:5191`，后端为 `http://127.0.0.1:8021`，数据库为全新临时 SQLite。

### 客户取消订单

- 页面：`/client/orders/{id}`。
- 先创建独立数量 1 订单；打开“确认取消订单”应用内弹窗，点击“返回”后没有发送取消请求。
- 再次打开弹窗并双击确认按钮，页面只产生一次 `POST /api/customer/orders/{id}/cancel`，显示“订单已取消”。
- 第三张独立数量 1 订单通过 Playwright 路由模拟后端 503，确认后弹窗保留并显示“隔离测试后端故障”；该步骤验证页面网络/后端失败反馈，没有修改真实服务状态。

### 数量 2 连续交付

- 页面：`/admin`，目标订单数量为 2。
- 第一次页面填写节点 ID、隔离 IP `198.51.100.21` 和到期时间，提交应用内交付确认后，页面显示 `partially_delivered` / “部分交付”，并保留“手动交付”入口。
- 第二次从同一订单卡片再次填写交付信息，使用隔离 IP `198.51.100.22`，提交后页面显示 `delivered` / “已交付”。
- 客户页面：`/client/lines` 显示两个隔离 IP；线路详情页显示“线路交付信息将在开通后显示”，没有真实链接。
- 管理员重新读取已完成订单页面后，目标订单没有可见“手动交付”入口，证明完成后不能继续交付。

最终隔离数据库核对：目标订单 `quantity=2`、`delivered_quantity=2`、`status=delivered`；线路为两条；`node_link`、`subscription_url`、`node_qr_data`、`subscription_qr_data` 全部为 `null`。

本轮 Playwright 过程中的一次失败是初始脚本使用全页面隐藏按钮数量判断交付入口，已改为目标订单卡片的可见按钮并通过客户/管理员页面复验；不属于页面业务失败。
