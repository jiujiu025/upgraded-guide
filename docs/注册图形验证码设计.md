# 注册图形验证码设计

> 目标：把"客户自助注册"这个口从"换 IP 就能批量刷号"收紧到"得先看懂一张图"。
> 不上邮箱验证、不上短信验证，只加一道点选图形——成本最低、体验最快。

## 1. 为什么自建，不接第三方

考虑过 reCAPTCHA、hCaptcha、极验，最终自建，理由三条：

1. **可达性**：客户主要在国内，Google 系域名多数网络环境打不通；接一个打不开的
   验证码，等于把注册入口关掉。
2. **数据边界**：第三方验证码要求把每一次注册的浏览器指纹交给外部服务，为了挡
   脚本把客户信息送出去，不划算。
3. **够用**：这里要挡的是脚本批量注册和爬虫刷号，不是专业打码平台。点选图形 +
   一次性 token + 限流，足以把成本抬到"不如人工注册"的程度。

## 2. 形态

3×3 九宫格，每格一张图，题目是「请点选图中所有『星星』（共 3 张）」。

- 图形库 13 个：星星、爱心、闪电、月亮、房子、水滴、十字、三角、方块、圆形、
  菱形、六边形、圆环。每题抽 1 个当目标，另抽 3~4 格放目标图形，其余放干扰图形。
- 每格随机上色、随机旋转、随机缩放，叠噪声点和细线——同一道题重复出现也不会
  长得一样。
- 方块单独限制旋转幅度（±10°）。转到 30° 以上就成菱形了，客户会把干扰项当成
  答案，这是第一版样张目视检查时发现的问题。

## 3. 答案怎么藏

**答案加密在 token 里，响应里只有图形。**

- token = `v1:` + base64(nonce‖AES-GCM(答案 JSON))，密钥由 `JWT_SECRET_KEY`
  SHA-256 派生，AAD 固定为 `99ipxin:captcha:v1`。
- 客户拿到的是密文，扒 DOM、翻 localStorage 都读不出该选哪几张。
- 图形是服务端现画的 SVG 路径，**不含一个文字**。这一点很关键：如果用 emoji 或
  文字渲染，答案会以字符形式落在页面里，脚本直接抄。
- 前端把 SVG 转 data URI 塞进 `<img>`，不用 `v-html`——img 里的 SVG 不能执行脚本。

## 4. 判题与防重放

| 规则 | 处理 |
| --- | --- |
| 选错 | 不消耗题目，但计一次错 |
| 同一题错满 3 次 | 题目作废，必须换题（防止拿一道题试完 2^9 组合） |
| 验证通过 | token 立刻标记已用，同一 token 第二次提交直接拒 |
| 超过 180 秒 | 过期，重新出题 |
| token 被篡改 | AES-GCM 校验失败，统一提示"不正确" |

去重状态放 Redis（`ops:captcha:used:*` / `ops:captcha:wrong:*`），多实例共享：
一道题在 A 实例用掉，B 实例不能认。生产强制 `RATE_LIMIT_BACKEND=redis`，所以这条
链路必然生效；Redis 抖动时降级到进程内记录并打 warning——验证码是防刷手段，不该
因为缓存故障把注册整体打死。

## 5. 接口

`GET /api/public/captcha`（每 IP 30 次/分钟，`CAPTCHA_RATE_LIMIT`）

```json
{
  "token": "v1:...",
  "target": "星星",
  "count": 3,
  "expires_in": 180,
  "tiles": [{ "index": 0, "svg": "<svg ...>...</svg>" }]
}
```

`POST /api/public/register` 新增两个字段：

```json
{ "captcha_token": "v1:...", "captcha_selection": [0, 4, 8] }
```

- 校验放在**最前面**：先过验证码，再查用户名占用、邮箱重复。否则这些可探测的
  信号可以绕过验证码白拿。
- 失败统一 400 + 中文原因（`请先完成图形验证码` / `图形验证码不正确，请重新选择`
  / `图形验证码已过期，请刷新后重试` / `图形验证码已使用，请刷新后重试` /
  `验证失败次数过多，请刷新验证码后重试`）。
- 字段在 schema 里是可选的，仅为在路由里回中文提示；缺字段直接 422 会给出英文
  校验信息。

## 6. 前端

`components/ImageCaptcha.vue`：

- 挂载即出题；右上角刷新换题；点选/取消点选；已选数量有提示。
- 只负责收集 `{token, selection}`，不做本地判题。
- 注册失败后自动换题：这道 token 在服务端已经用掉或作废，留着也没用。
- 加载失败（比如撞上限流）显示原因并保留刷新按钮，不阻塞用户重试。

`AuthPanel.vue` 在注册表单里挂载组件，提交前校验"至少选了一张"，否则提示
「请先点选图片完成安全验证」。

## 7. 配置

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CAPTCHA_RATE_LIMIT` | 30 | 出题接口每 IP 每分钟上限 |

题目有效期 180 秒、错 3 次作废写死在 `captcha_service` 常量里，不做成配置——
调大只会削弱防护，没有运营价值。

## 8. 已知边界

- 能挡脚本批量注册，**挡不住**带视觉模型的定向攻击。真要防到那一步，得上滑块
  轨迹、设备指纹或人工审核，成本和误伤都会上一个量级。
- 客户如果开了深色模式或护眼滤镜，图形对比度会下降；目前配色按浅底深图设计，
  暂不做深色主题适配。
- 邀请码校验接口、找回密码接口暂未接入验证码；如果要防"拿手机号/用户名探活"，
  下一步应把 `/public/invite-codes/{code}` 也挂上。
