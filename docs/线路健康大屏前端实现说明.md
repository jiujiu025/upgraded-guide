# 线路健康大屏前端实现说明

## 页面与权限范围

### 管理员 `/admin/health`

- 展示线路总数、正常、异常、离线、平均延迟、受影响客户和未处理故障。
- 展示故障事件、地区健康统计、产品类型健康统计和全量线路列表。
- 支持状态、地区、产品、负责人和关键词筛选。
- 点击线路打开详情抽屉，查看检测时间线、受影响客户和处理记录。
- 发起检测、确认故障、进入维护和静默操作均为交互原型，不会修改后端。

### 销售 `/sales/health`

- 只展示当前登录销售名下的演示线路、故障事件和受影响客户。
- 不展示全平台线路数、全平台故障数或其他销售的客户数据。
- 联系客户、查看客户和查看订单均为交互入口原型，不会发送消息或修改业务数据。

## 演示数据

健康数据统一存放在 `frontend/src/mocks/health.js`，通过 `loadHealthFixture` 加载。管理员获得完整演示数据；销售按 `ops_user.username` 裁剪后获得自己的演示数据。

页面顶部持续显示“演示数据”标识，并注明数据来自独立 fixture，不代表真实线路状态。

可使用以下地址检查特殊状态：

- `/admin/health?demo=empty`：空数据状态。
- `/admin/health?demo=error`：加载错误与重试状态。

当前健康页面不调用真实健康 API，也没有修改现有 Axios 封装和认证流程。

## 响应式策略

- 1440、1280：完整统计、并排地区/产品统计和数据表格。
- 768：统计重新分栏，筛选器收缩，线路表格转换为卡片。
- 390：单列筛选、紧凑状态摘要、单列线路卡片，详情抽屉占满屏幕。
- 异常线路固定按离线、异常、延迟升高、待检测、正常排序。

## 后续真实 API 清单

建议后端联调时提供以下接口：

- `GET /api/admin/health/summary`：管理员全平台健康汇总。
- `GET /api/admin/health/incidents`：管理员故障事件列表及筛选。
- `GET /api/admin/health/lines`：管理员线路健康列表及筛选、分页。
- `GET /api/admin/health/lines/{id}`：线路时间线、影响客户和处理记录。
- `POST /api/admin/health/lines/{id}/check`：发起线路检测。
- `POST /api/admin/health/incidents/{id}/confirm`：确认故障。
- `POST /api/admin/health/incidents/{id}/maintenance`：进入或结束维护。
- `POST /api/admin/health/lines/{id}/silence`：设置静默时间。
- `GET /api/sales/health/summary`：当前销售客户范围健康汇总。
- `GET /api/sales/health/incidents`：当前销售客户范围故障事件。
- `GET /api/sales/health/affected-customers`：受影响客户、线路、到期时间及关联订单。

接口必须在后端完成角色和数据范围校验，前端不应通过全量数据过滤模拟销售权限。
