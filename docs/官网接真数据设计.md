# 官网接真数据（已实施）

> 状态：**已实施（2026-11-09）**。目标：官网展示的产品、地区、价格、库存、下单链路全部来自业务系统，不再有"看起来像数据、其实是写死"的内容。

## 0. 一句话结论

官网原来**不是完全假的**——产品列表、算价、下单其实早就调后端了。真正假的是三类东西：

1. **产品详情页只有 6 行代码**，没有价格档位，所有产品共用一套通用文案；
2. **首页统计数字写死**（4 个产品类型 / 10 个地区 / 3 种交付形式）；
3. **文章页所有 slug 渲染同一篇**，`/help/clash`、`/help/v2ray`、`/guide/xxx` 点进去内容一模一样。

本轮把这三类处理掉，并补了一个面向官网的目录接口，避免供应商同步后 SKU 铺满首页。

## 2. 后端：面向官网的目录接口

逐 SKU 展开在供应商同步之后会失控：一个分类 × 10 个国家 × 4 个周期 = 40 条商品，直接铺到首页就是一堵墙。所以新增一层**分类聚合**。

### 2.1 `GET /api/public/catalog`

```json
{
  "categories": [
    { "code": "static_residential", "name": "独享静态住宅（普通）", "kind": "catalog",
      "min_price": 60.0, "periods": [30, 90, 180, 360], "region_count": 10, "in_stock": true,
      "regions": [{ "id": 1, "name": "美国", "country_code": "US", "min_price": 60.0, "in_stock": true }] }
  ],
  "product_count": 40,
  "region_count": 10
}
```

- 按 `resource_category` 聚合；固定价商品（`resource_category` 为空，如直播专线）各自成组，`code = fixed-<id>`，保证 URL 是 ASCII。
- 列表**不返回**逐地区价格明细，只给起价与覆盖地区，控制响应体积。
- 停用商品、停用地区不出现。

### 2.2 `GET /api/public/catalog/{code}`

在列表结构上多一层 `regions[].offers[]`：

```json
{ "code": "static_residential", "periods": [30, 90],
  "regions": [{ "name": "日本", "in_stock": true,
    "offers": [{ "product_id": 7, "billing_days": 30, "unit_price": 80.0, "in_stock": true }] }] }
```

详情页据此渲染「地区 × 周期」价格表，每个格子就是一个可下单的 `product_id`，点「开始选购」直接把 `product_id` 带到选购页，不需要前端反查。

两个接口都吃公开限流（`PUBLIC_RATE_LIMIT`），未知 code 返回 404。

## 4. 内容边界（刻意不做的事）

- **不编造产品卖点**：不写"延迟 30ms""99.9% 可用""解锁某平台"——产品库里没有这些数据。详情页只讲价格、周期、地区、库存、交付形式。
- **不承诺平台结果**：与销售册口径一致，住宅 / 原生 / 静态 / 独享是四个不同属性，官网文案不混用。
- **文章不做 CMS**：教程与资源属于内容，不接后端；但按 slug 渲染真实条目，不再"所有链接同一篇"。
- **不做 SSR / SEO 预渲染 / 多语言**：官网是 SPA，本轮不引入框架级改造；如果后面要做 SEO，再单独评估。
- **不开放免登录下单**：下单仍需客户账号，这是资金链路的前提。

## 5. 验收

后端（`tests/test_public_catalog.py`，5 条）：

1. 同一分类 × 多个国家 × 多个周期 → 聚合成一个分类、`region_count` 正确、`min_price` 取最低周期价；
2. 列表不返回 `offers`，详情才返回；
3. 固定价商品单独成组，价格正确；
4. 停用商品不出现；未知 code 404；
5. 走公开限流（第 N+1 次 429）。

前端（`tests/ArticlePage.test.js`，3 条）：不同 slug 标题不同、未知 slug 明确提示、目录锚点与正文标题一一对应。

构建：`vite build` 通过；既有 22 条前端测试与 327 条后端测试全部保持绿色。

## 6. 已知限制

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 首页视觉图 `network-topology.png` 上的 `US/NEW YORK`、`JP/TOKYO` 标签 | 仍是装饰性文案 | 它标注的是示意图，不是实时节点；如果要改成实时，需要暴露节点在线数（涉及安全口径，暂不做） |
| 分类名称 | 直接用 `product_type` | 后端没有独立的分类营销名；要更好听的名字得再加一层映射或后台配置 |
| 产品详情无图片 | 产品库没有图片字段 | 现在用价格表撑版面；要产品图得先给 `products` 加字段并配套上传 |
