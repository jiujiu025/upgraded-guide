# 官网接真数据（已实施）

> 状态：**已实施（2026-11-09）**。目标：官网展示的产品、地区、价格、库存、下单链路全部来自业务系统，不再有"看起来像数据、其实是写死"的内容。

## 0. 一句话结论

官网原来**不是完全假的**——产品列表、算价、下单其实早就调后端了。真正假的是三类东西：

1. **产品详情页只有 6 行代码**，没有价格档位，所有产品共用一套通用文案；
2. **首页统计数字写死**（4 个产品类型 / 10 个地区 / 3 种交付形式）；
3. **文章页所有 slug 渲染同一篇**，`/help/clash`、`/help/v2ray`、`/guide/xxx` 点进去内容一模一样。

本轮把这三类处理掉，并补了一个面向官网的目录接口，避免供应商同步后 SKU 铺满首页。

## 1. 现状盘点（改造前）

| 页面 | 数据来源 | 结论 |
| --- | --- | --- |
| 首页产品卡 / 产品列表 | `GET /api/public/products` | ✅ 真数据，但**逐 SKU 平铺**，且卡片卖点是用 `region`/`product_type` 拼出来的 |
| 产品详情 | 同上 + 前端拼装 | ❌ 无价格档位；`summary`/`platforms`/`delivery` 是编的 |
| 选购 / 算价 | `GET /api/public/products` + `POST /api/public/orders/preview` | ✅ 真数据，价格由后端算 |
| 结算下单 | `POST /api/customer/orders` | ✅ 真数据，需要客户登录 |
| 首页统计条 | 写死 `4 / 10 / 3 / 24-7` | ❌ |
| 教程 / 资源 / 文章 | `src/mocks/data.js` + 单篇静态模板 | ❌ 所有 slug 同一篇 |

## 2. 后端：面向官网的目录接口

逐 SKU 展开在供应商同步之后会失控：一个分类 × 10 个国家 × 4 个周期 = 40 条商品，直接铺到首页就是一堵墙。所以新增一层**分类聚合**。

### 2.1 `GET /api/public/catalog`

```json
{
  "categories": [
    { "code": "static_residential", "name": "独享静态住宅（普通）", "kind": "catalog",
      "min_price": 60.0, "periods": [30, 90, 180, 360], "region_count": 10, "in_stock": true,
      "regions": [{ "id": 1, "name": "美国", "country_code": "US", "min_price": 60.0, "in_stock": true }] }
  ],
  "product_count": 40,
  "region_count": 10
}
```

- 按 `resource_category` 聚合；固定价商品（`resource_category` 为空，如直播专线）各自成组，`code = fixed-<id>`，保证 URL 是 ASCII。
- 列表**不返回**逐地区价格明细，只给起价与覆盖地区，控制响应体积。
- 停用商品、停用地区不出现。

### 2.2 `GET /api/public/catalog/{code}`

在列表结构上多一层 `regions[].offers[]`：

```json
{ "code": "static_residential", "periods": [30, 90],
  "regions": [{ "name": "日本", "in_stock": true,
    "offers": [{ "product_id": 7, "billing_days": 30, "unit_price": 80.0, "in_stock": true }] }] }
```

详情页据此渲染「地区 × 周期」价格表，每个格子就是一个可下单的 `product_id`，点「开始选购」直接把 `product_id` 带到选购页，不需要前端反查。

两个接口都吃公开限流（`PUBLIC_RATE_LIMIT`），未知 code 返回 404。

## 4. 内容边界（刻意不做的事）

- **不编造产品卖点**：不写"延迟 30ms""99.9% 可用""解锁某平台"——产品库里没有这些数据。详情页只讲价格、周期、地区、库存、交付形式。
- **不承诺平台结果**：与销售册口径一致，住宅 / 原生 / 静态 / 独享是四个不同属性，官网文案不混用。
- **文章不做 CMS**：教程与资源属于内容，不接后端；但按 slug 渲染真实条目，不再"所有链接同一篇"。
- **不做 SSR / SEO 预渲染 / 多语言**：官网是 SPA，本轮不引入框架级改造；如果后面要做 SEO，再单独评估。
- **不开放免登录下单**：下单仍需客户账号，这是资金链路的前提。

## 7. 2026-11-09 产品模型调整（三条产品线 + 价格登录可见）

### 7.1 产品线

官网只展示三条线，国家清单三条完全一致（全部启用地区，共 34 个）：

| 产品线 | 分类编码 | 定价方式 |
| --- | --- | --- |
| 静态住宅IP（运营商原生 IP） | `static_residential` | 按国家，30 天价；90/180/360 线性派生 |
| 社媒运营专线 | `social_media` | 按国家，30 天价（独立报价表，不与住宅价成固定比例） |
| 直播专线 | `live_stream_mobile` / `live_stream_pc` | 不分国家：手机 600、电脑 1100（30 天） |

直播拆成两个分类是因为价目表唯一约束是 (分类, 国家, 周期)，同一分类给不出"手机/电脑"两个价；
官网把两个分类合并到「直播专线」一条线里，用 `spec` 字段区分规格。

### 7.2 分类口径：官网那条住宅线就是运营商原生 IP

业务确认（2026-11-10）：**官网只上架静态住宅这一类，而它卖的是运营商原生 IP（ISP 原生），
不是机房伪装住宅。** 因此分类的中文名从「独享静态住宅（普通）」改为「静态住宅原生IP」。

这里有两套命名，各管一头，不要混：

| 用途 | 取值来源 | 住宅线叫法 |
| --- | --- | --- |
| 后台分类下拉、供应商侧分类 | `supplier_service.RESOURCE_CATEGORY_CODES` | 静态住宅原生IP |
| 商品名、官网产品线标题 | `site_catalog.CATEGORY_LABELS` / `LINE_LABELS` | 静态住宅IP |

为什么分开：客户看的是"买什么"（静态住宅 IP，短名才好读），运营看的是"这条线到底是什么资源"
（原生 IP，不能写成含糊的"普通"）。供应商同步新建商品时用短名，分类下拉用技术名。

历史分类（`static_residential_native` / `static_residential_isp` / `static_datacenter`）**不再售卖**，
后台下拉里会带「已停售，不上官网」后缀，但仍可查改历史价则。判断在售与否看
`site_catalog.ACTIVE_CATEGORIES`。

官网详情页对住宅线额外展示一句 `subtitle`：**运营商原生 IP（ISP 原生），非机房伪装住宅**。
这句来自后端 `LINE_SUBTITLES`，只在有依据的线上出现，社媒和直播返回 null（不显示）。

### 7.3 数据落地

新增 `app/data/site_catalog.py`（国家清单 + 两张报价表）与 `scripts/seed_site_catalog.py`：

```
python scripts/seed_site_catalog.py           # 预演
python scripts/seed_site_catalog.py --apply   # 写库
```

脚本是幂等的：地区按名称、价格按 (分类, 国家, 周期)、商品按名称匹配，重复执行只更新不重复插入。
同一个国家代码下的旧命名地区（如"香港" vs "中国香港"）会被**停用**，避免官网出现两个香港。

后台「商品与价格」页可以直接改价：分类下拉已包含三个新分类，改 30 天价会自动回写商品展示价；
国家名称以 Region 为准（返回 `country_name`），不再依赖浏览器 `Intl.DisplayNames` 猜。

### 7.4 价格可见性

| 接口 | 未登录 | 登录后 |
| --- | --- | --- |
| `GET /api/public/catalog` | 产品线 / 国家 / 周期，**无价格** | — |
| `GET /api/public/catalog/{code}` | 同上，`offers` 为空 | — |
| `GET /api/catalog` | 401 | 起价 + 逐地区逐规格报价 |
| `GET /api/catalog/{code}` | 401 | 同上（单条产品线） |
| `POST /api/public/orders/preview`（算价） | **401** | 正常返回单价与合计 |

算价接口原来是免登录的，等于绕开"登录可见价"直接拿报价；现在一并收紧。
官网组件按登录状态选择接口：未登录只渲染国家与周期，价格位置显示「登录查看价格」并带 redirect 去登录页，
登录后自动回到原页面。**服务端脱敏，不是前端藏起来。**

### 7.5 已知缺口

2026-11-10 与玖夜确认：**以下缺口全部保持现状，不补价、不加国家**。缺口不影响售卖，
官网对缺价国家的表现是「暂无报价 + 按钮禁用」，不会出现空价、`¥null` 或可下单但失败。

| 项 | 现状 | 决策 |
| --- | --- | --- |
| 静态住宅缺 1 国 | 俄罗斯：原报价表没有该行，官网显示"暂无报价"，`/api/catalog` 返回 `min_price: null` | 先空着（不确定住宅线在俄有无货，空着比乱标价安全） |
| 社媒缺 11 国 | 荷兰 / 波兰 / 匈牙利 / 保加利亚 / 丹麦 / 土耳其 / 以色列 / 阿联酋 / 孟加拉 / 巴基斯坦 / 南非 | 暂不上架，保持"暂无报价" |
| 12 国报价闲置 | 柬埔寨 / 缅甸 / 马里 / 希腊 / 莫桑比克 / 刚果金 / 加纳 / 老挝 / 卡塔尔 / 肯尼亚 / 捷克 / 罗马尼亚：报价表有静态住宅价，但不在 34 国清单里 | 暂不上架，报价留在库里 |
| 日本社媒两行价 | 原表 115 与 123 两行，唯一约束只允许一条，取较高值 123 | 可后台改 |
| `/api/public/products` 仍返回价格 | 选购页已对未登录用户隐藏价格并停止算价，但该接口本身仍带价格字段 | 后续项，关闭需改 8 处供应商测试 |

**为什么不自动按比例补价**：现有 23 国的社媒价相对住宅价的差价是 11～44 元不等（倍率 1.111～1.583），
没有固定规律（美国 +35、香港 +34、巴西 +44、印尼 +11）。用均值推断等于替客户定价，
而价格会直接展示给客户并进入财务对账，所以宁可空缺也不猜。

**缺口怎么查**（只读，随时可跑，不改数据）：

```
python scripts/price_gaps.py
```

输出三段：各产品线缺价国家、属于三条线但无地区记录的闲置报价、有价则但无可下单商品的坏数据。
它只统计**在售分类**（`site_catalog.ACTIVE_CATEGORIES`）——历史分类（机房 / ISP 原生 / 本土原生，
共 198 条 30 天价则）已不对外售卖，只报数量，不逐条列出，否则几十行噪音会淹掉真正的缺口。
