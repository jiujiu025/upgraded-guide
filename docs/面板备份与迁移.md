# 面板备份与迁移

> 目标：旧面板不行了，能把配置整体搬到新机器，**客户链接不用重发**，
> 只改一下域名解析就完成迁移。

## 1. 备份里有什么

一份备份 = 平台侧配置 + 面板上的全部定义：

| 部分 | 内容 | 为什么必须有 |
| --- | --- | --- |
| `vps` | 名称、区域组、连接地址、SNI/dest/fingerprint、端口段、承载上限 | 恢复后选机、拼链接要用 |
| `inbounds` | 每条入站的**完整**定义：端口、协议、clients（UUID/email）、streamSettings（reality 私钥、shortId、serverNames）、sniffing | 缺任何一项，客户手里的链接就失效 |
| `xray.outbounds` | 全部出站（socks5 指向住宅 IP、direct、blocked…） | 没有出站，入站就没法落地 |
| `xray.rules` | 路由绑定（`inbound-{port}` → 出站 tag） | 没有路由，入站走默认出口（VPS 本机 IP） |

**不需要**备份的是客户链接本身：只要端口、UUID、私钥、shortId 一致，链接就不变。
客户端里的地址如果是域名，那更简单——DNS 指到新机器即可。

## 2. 文件在哪

- 默认目录：`backend/data/transit-backups/`（已在 `.gitignore` 里）
- 可用环境变量覆盖：`TRANSIT_BACKUP_DIR=/data/transit-backups`
- 文件名：`{面板名}-{UTC时间戳}.json.gz`，gzip 压缩
- 权限 `600`：里面有私钥和客户 UUID，只给超级管理员下载

> **容器部署要挂卷**：把 `TRANSIT_BACKUP_DIR` 指向持久化卷，否则重建容器时备份会跟着没。
> 生产 compose 里给 api 服务加一条 volume 即可。

## 3. 迁移步骤

1. **备份旧面板**：后台「中转面板 → 备份与迁移」，选面板点「立即备份」，
   列表里出现一条 `可用` 记录（能看到入站/出站/路由数量与文件大小）。
2. **准备新机器**：装同版本 3x-ui，确认能访问面板。
3. **录入新面板**：在「面板」tab 新建一台，`connect_host` 填新机器的 IP 或**同一个域名**，
   **先保持停用**（避免新单落到还没恢复的机器上）。
4. **恢复**：回备份列表点「恢复」→ 选新面板 → 「预检冲突」→
   确认「将新建」数量与预期一致 → 「确认恢复」。
   - 预检会列出端口冲突：目标面板上已占用的端口会被**跳过**，不会覆盖别人的业务；
   - 执行后逐条建入站、合并出站与路由、重启一次 Xray；
   - 结果显示新建/跳过/失败明细。
5. **切 DNS**：确认新面板上线路可用后，把域名 A 记录改成新机器 IP。
   - 如果客户链接里写的是域名，这一步就是全部；
   - 如果写的是裸 IP，需要在平台侧把 `connect_host` 改成域名后再让客户换一次链接。

## 4. 注意事项

- **恢复会重启目标面板的 Xray**：如果目标面板上已经有客户线路，会瞬断 1–3 秒。
  迁移场景目标通常是空面板，不受影响。
- **同端口跳过**意味着"这条没恢复"：迁移到空面板时不应出现；出现了说明目标不是空的，
  先人工确认再决定是否清空重来。
- **备份不含面板账号密码**：恢复用的是目标面板自己的凭据，所以新机器不必和旧机器同密码。
- **递归备份**：备份只读面板，不写面板，可以对同一台反复备份，用于"迁移前留一份"。
- 备份文件含敏感信息，**下载后别随手丢在共享盘**；确认迁移完成后可以删除旧备份。

## 5. 接口

```
POST   /api/admin/transit/vps/{vps_id}/backups        立即备份
GET    /api/admin/transit/backups?vps_id=&status=     备份列表
GET    /api/admin/transit/backups/{id}/download       下载（需 Bearer）
POST   /api/admin/transit/backups/{id}/restore        {target_vps_id, dry_run}
DELETE /api/admin/transit/backups/{id}                删除记录与文件
```

全部限定 `super_admin`：下载里有私钥，恢复是覆盖性操作。

## 6. 测试

`backend/tests/test_transit_backup.py`：

- 备份文件里必须带着端口、UUID、reality 私钥（缺一项客户链接就废了）
- 只有 super_admin 能操作
- dry-run 只报冲突、不写面板
- 恢复会重建入站并补出站/路由，且不重复添加目标已有的 `direct/blocked`
- 下载返回可解压的归档；删除会同时删文件与记录

前端 `tests/TransitBackupPanel.test.js`：列表、立即备份、预检冲突、确认恢复、删除确认。
