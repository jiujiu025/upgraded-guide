# 管理员模拟登录设计（销售 / 客户视角）

> 目标：超级管理员能"以某个销售或客户的身份看一遍"，用于排查客户报障、核对页面权限、
> 复现下单问题。不是"替客户操作"，也不是"随时切换账号"。

## 1. 威胁模型（不解决这些就等于开了后门）

| 风险 | 后果 | 对策 |
| --- | --- | --- |
| 模拟 token 与真实会话混用 | 退出模拟后仍是对方身份，或对方会话被顶掉 | 独立 token 类型 + 独立表，**不复用** `AuthSession` |
| 审计断链 | 客户的操作其实是管理员做的，出事查不到人 | 审计同时记 actor（管理员）与 target（被模拟者），不覆盖 |
| 忘记退出 | 管理员把笔记本一合，回来还是客户身份 | 服务端 10 分钟硬过期 + 前端倒计时 + 到期自动清理 |
| 同时开两个标签串台 | 两个身份互相覆盖，模拟 A 变成模拟 B | token 存 **sessionStorage（按标签隔离）**，不写全局 cookie |
| 链式模拟 | 模拟销售后再模拟客户，责任链断掉 | 模拟态禁止再发起模拟 |
| 越权 | 模拟态下改密码、退款、删数据 | 默认**只读**，敏感路径后端直接 403 |

## 2. 核心设计

### 2.1 独立 token，不碰真实会话

新增表 `impersonation_sessions`：

| 字段 | 说明 |
| --- | --- |
| `actor_id` | 发起人（必须 super_admin） |
| `target_user_id` | 被模拟的销售/客户账号 |
| `token_hash` | 随机 token 的 HMAC，明文只在签发时返回一次 |
| `started_at / expires_at` | 固定 10 分钟，不续期 |
| `ended_at / end_reason` | `manual` / `expired` / `actor_revoked` |
| `actor_ip / user_agent` | 留痕 |
| `last_seen_at` | 便于判断是否还在用 |

token 是随机串（`secrets.token_urlsafe(32)`），不走 JWT：JWT 无法在 10 分钟内"立刻吊销"，
而这套功能要求管理员在后台点一下就能掐断。

### 2.2 鉴权分流

`current_user` 先看 token 前缀：

- 普通 access token → 现有逻辑不变；
- 模拟 token（`imp_` 前缀）→ 查 `impersonation_sessions`：
  - 未结束、未过期、actor 仍 active 且仍是 super_admin；
  - 取出 target user 作为当前身份（角色、权限都按 target 算）；
  - 把 actor_id 放进 `ContextVar`，供审计与"当前是模拟态"判断使用。

任何一条不满足 → 401，前端立即退出模拟。

### 2.3 只读策略

模拟态下**只允许 GET/HEAD**。理由：这个功能是"看对方看到什么"，不是替对方操作；
一旦允许写，就要穷举"哪些写不能做"（改密、支付、退款、删除、发起工单……），
漏一个就是事故。

例外：`POST /api/auth/logout-impersonation`（结束模拟本身）。

### 2.4 审计

`write_audit` 增加两个可选参数 `impersonated_user_id` 与 `on_behalf_of`，
在模拟态下自动带出：`actor=管理员`，`target=客户/销售`。审计页能按"模拟操作"筛出来。

### 2.5 两个标签同时模拟

1. 后台点「模拟登录」→ `POST /api/admin/impersonation` 拿到 `token`；
2. `window.open('/sales#imp=<token>')` 打开**新标签**；
3. 新标签读取 hash 里的 token → 写入自己的 `sessionStorage` → 从地址栏抹掉（hash 不进服务器日志）；
4. 每个标签的 `sessionStorage` 天然隔离，两个身份互不覆盖；
5. 关闭标签 = 结束（`beforeunload` 尽力而为，服务端仍以 10 分钟兜底）。

### 2.6 到期与退出

- 服务端：每次请求校验 `expires_at`，过期即 401 并把记录标 `expired`；
- 前端：进入模拟态起一个倒计时，剩 60 秒变红提示，到点清 storage、跳回 `/admin`；
- 顶部常驻横幅：`正在以「深圳乙公司」身份查看（只读）· 剩余 09:58 · 退出模拟`；
- 后台「模拟登录记录」列出进行中的会话，可**强制结束**（管理员关掉笔记本时用）。

## 3. 接口

```
POST   /api/admin/impersonation            {user_id} → {token, expires_at, user}
DELETE /api/admin/impersonation/{id}       强制结束（super_admin）
GET    /api/admin/impersonation            进行中 + 最近记录（含 actor/target/剩余时间）
POST   /api/auth/impersonation/logout      模拟态自己退出
GET    /api/auth/me                        模拟态额外返回 impersonation: {actor, expires_at}
```

## 4. 允许模拟谁

- 只能模拟 `role in (sales, customer)` 且 `is_active` 的账号；
- 不能模拟管理员、不能模拟已停用账号、不能模拟自己；
- 一个管理员同时最多 3 个进行中的模拟（防误点开一堆标签）；
- 客户账号必须已绑定 `Customer` 且未删除，否则进去也是空页面，没有意义。

## 5. 前端入口

- 销售管理页：每行「模拟登录」（仅 super_admin 可见）；
- 客户管理页：每行「模拟登录」；
- 顶部横幅组件全局挂在 `/sales`、`/client` 布局上，模拟态才渲染；
- 模拟态下隐藏「修改密码」「安全中心」等入口（后端也会拦）。

## 6. 验收

1. 超级管理员模拟销售：新标签打开，横幅与倒计时正确，数据是该销售名下客户；
2. 同一浏览器再开一个标签模拟客户：两个标签各自身份，互不覆盖；
3. 模拟态下调用 `POST /api/orders` 返回 403，`GET` 正常；
4. 10 分钟后刷新页面：401 → 自动回后台，记录标 `expired`；
5. 后台强制结束：对应标签下一次请求即 401；
6. 审计里能看到 `actor=管理员 / target=客户`，不是只有客户；
7. 普通 admin（非 super_admin）调接口返回 403。
