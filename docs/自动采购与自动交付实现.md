# 付款后自动采购静态住宅（实现说明）

> 目标：客户下单付款后，系统直接调上游买一条静态住宅 IP，拿到 IP + 端口 + 账密后
> 自动生成客户线路，不需要人工贴链接。资源池 1（全球代理）已按文档接完读写接口，
> 本文只说明「怎么把这条链接起来」。

## 1. 一句话流程

```
客户下单 → 余额支付 / 管理员确认收款
        → 后台任务 auto_procure_order
        → 幂等检查（procurements.order_id + line_index）
        → 参数映射（分类 / 国家 / 城市 / 段 / 周期 / 数量）
        → 上游 buy_static_ip（同步返回子账号）
        → 每条账号生成一条 CustomerLine（socks5:// 链接 + 订阅 + 二维码）
        → 订单 delivered / partially_delivered，通知客户
```

## 2. 触发点

| 入口 | 位置 | 说明 |
| --- | --- | --- |
| 客户余额支付 | `POST /api/wallet/orders/{id}/pay-balance` | 支付成功后 `BackgroundTasks` 触发 |
| 管理员确认收款 | `POST /api/admin/orders/{id}/confirm` | 确认后触发（线下转账场景） |

为什么放后台任务：上游下单最慢会卡到 HTTP 超时（默认 10 秒），放在支付请求里会让
客户以为付款失败、反复点支付。采购结果落在 `procurements` 表，不依赖日志。

## 3. 开关（默认关闭）

```dotenv
# .env.production
SUPPLIER_AUTO_PROCUREMENT_ENABLED=true
```

关闭时 `auto_procure_order` 直接返回，不产生任何采购记录，原有「人工交付」流程完全不变。
打开前必须先做两件事：

1. 在后台「资源池管理」录入全球代理的 API Key（或配 `GLOBAL_PROXY_API_KEY`）；
2. 用一笔小额真实订单验证：上游余额足够、返回的账号数等于订单数量。

## 4. 参数映射

| 订单字段 | 上游参数 | 规则 |
| --- | --- | --- |
| `product.resource_category` | `product_type_id` | 只采购 `static_residential`（上游 3=原生）；其他分类跳过 |
| `order.billing_days` | `timelen` | 7/30/90/180/360 → 0/1/2/3/4；其他档位落 `manual` 待人工 |
| `order.quantity` | `num` | 直接透传（上游 1-300） |
| `region.country_code` | `country` | 两位国家码 |
| `order.requested_city_code` | `city` | 换成 `catalog_city_options.city_name`（上游按名字下单） |
| `order.requested_ip_segment` | `appoint_ip[0][ip_str]` | 前两段，数量=订单数量 |
| `order.order_no` | `remark` | 上游查询兜底用 |

## 5. 幂等与失败处理（资金安全）

- **幂等键**：`procurements(order_id, line_index)` 唯一。重复触发只会真实下单一次；
  并发触发时第二个请求会撞唯一键，回滚后读已有记录返回。
- **失败不自动重试**：上游没有幂等键，超时后重试 = 重复扣款。失败记为 `failed`，
  订单留在 `pending_delivery` 转人工。
- **超时兜底**：上游支持 `accountList?remark=<订单号>` 查单；人工处理时先用它确认
  是否已经买到，再决定补单还是退款。
- **数量校验**：适配器会在 `assets 数量 != 下单数量` 时抛错，不猜。

## 6. 客户拿到的是什么

上游返回的是代理账号（IP + 端口 + 账号 + 密码），不是 vless 隧道，所以自动交付：

- 线路的 `static_ip` 写上游 IP；
- 节点链接拼成 `socks5://user:pass@ip:port#国家-静态IP`；
- 订阅与二维码复用已有链路（Clash 里是 `type: socks5`，小火箭/v2rayN 直接认这个链接）。

`proxy_link` 因此新增 `socks5` / `http` 解析，`to_clash_proxy` 把账号密码拆成
`username` / `password` 两个字段。

## 7. 可观测

- `procurements` 表：状态、上游单号、请求参数、上游返回（脱敏）、错误码与错误信息、生成的线路 id。
- 失败时给客户发通知（"已转人工处理，无需重复付款"）。
- 审计日志：`deliver` 由谁触发、订单进度。
